Requisitos

ParaPrecisa de
UsarUm navegador atual: Chrome e Edge 111+, Safari 16.4+, Firefox 121+. O Grin usa oklch(), :has(), <dialog> e módulos ES.
ServirQualquer servidor de arquivos estáticos. Abrir o HTML direto do disco (file://) não carrega os módulos: use, por exemplo, python3 -m http.server.
Mudar tokensNode.js 18+ (só para as ferramentas em tools/).

Arquivos que o projeto precisa

PastaPara quêObrigatória
styles/Fontes, variáveis, base e todos os componentes. docs.css e home.css são só deste site.Sim
assets/fonts/Geist e Geist Mono (licença OFL).Sim
components/O CSS de cada componente (importado por components.css) e o JavaScript dos que têm comportamento.Sim
scripts/theme.js (preferências) e utils.js (ícones, contraste).Sim
tokens/, tools/Fonte dos valores e as ferramentas que geram e conferem o CSS.Só para mudar tokens

Mantenha as pastas juntas, numa pasta grin/ do projeto: os caminhos entre os arquivos são relativos.

Incluir na página

No <head> de cada página, nesta ordem. O primeiro script aplica o tema salvo antes da primeira renderização.

<script>/* Grin: apply the saved theme, density and font size before the first paint */try{var r=document.documentElement,p=new URLSearchParams(location.search),t=p.get('theme')||localStorage.getItem('grin-theme'),c=p.get('contrast')||localStorage.getItem('grin-contrast');if(t==='hc'){t='light';c='more';}if(t&&t!=='system')r.dataset.theme=t;if(c&&c!=='system')r.dataset.contrast=c;if(localStorage.getItem('grin-density')==='compact')r.dataset.density='compact';var s=localStorage.getItem('grin-scale');if(s&&s!=='100')r.dataset.scale=s;}catch(e){}</script>

Tema e preferências

Sem atributos, o Grin usa o tema e o contraste do sistema operacional. Os atributos valem na tag <html> ou em qualquer seção.

AtributoValoresEfeito
data-themelight, darkFixa o tema.
data-contrastmore, normalAlto contraste no claro ou no escuro (texto 7:1); normal desliga mesmo se o sistema pedir.
data-densitycompactControles de 36 px e texto de 14 px (padrão: 44 px e 16 px).
data-scale112, 125Fonte em 112,5% ou 125%. Os tamanhos em rem acompanham.
import { setTheme, setContrast, setDensity, setScale, effectiveTheme, effectiveContrast } from './grin/scripts/theme.js';

setTheme('dark');          // 'system' | 'light' | 'dark'
setContrast('more');       // 'system' | 'more' | 'normal'
setDensity('compact');     // 'comfortable' | 'compact'
setScale('112');           // '100' | '112' | '125'

document.documentElement.addEventListener('grin:theme', (e) => {
  console.log(e.detail);   // { theme: 'dark', contrast: 'more' }
});

Com React, Vue ou outro framework

O Grin não depende de framework: são classes CSS e módulos ES. Coloque a pasta no projeto (ou em public/) e importe.

// React, Vue, Svelte… : importe o CSS uma vez, na entrada do app
import 'grin/styles/fonts.css';
import 'grin/styles/variables.css';
import 'grin/styles/global.css';
import 'grin/styles/components.css';
import 'grin/scripts/theme.js';             // tema, contraste, densidade, fonte

// Comportamentos: só os que a tela usa. Todos escutam no document,
// então funcionam com elementos criados depois (renderização do framework).
import 'grin/components/dialog/dialog.js';
import { toast } from 'grin/components/toast/toast.js';
import { startTour } from 'grin/components/tour/tour.js';

// JSX: class vira className; o resto do markup é igual ao da documentação
<button className="btn primary">Salvar</button>

Mudar um token

Os valores vivem em tokens/ (JSON) e styles/variables.css é gerado a partir deles: nunca edite o CSS gerado à mão.

# 1. edite os valores em tokens/*.json
# 2. gere o CSS e confira
node tools/build-tokens.mjs     # escreve styles/variables.css
node tools/check-contrast.mjs   # contraste nos 4 temas (falha abaixo do mínimo)
node tools/check-markup.mjs     # toda classe e ícone usados existem

Adotar o Grin num projeto existente

Para ferramentas que já existem e vão trocar o próprio estilo pelo Grin.

Obrigatório em toda ferramenta

Toda ferramenta feita com o Grin tem estas partes, iguais às dos exemplos. Não substitua nenhuma por uma versão própria.

  • Barra lateral do Grin com sidebar.js. O botão redondo na borda recolhe e expande a barra, e no celular ela vira um drawer. Não crie outro botão de recolher.
  • Logo com o nome e a versão da ferramenta numa .tag ao lado, como "Vezen 4.0.1".
  • O desenho do logo cabe num quadrado de 24 × 24 px. Um desenho mais largo ou mais alto que o quadrado é reduzido até caber, mantém a proporção e fica centralizado. Use width e height de 24 px no SVG, com o viewBox do desenho.
  • Botão de tema com data-theme-toggle no rodapé da barra lateral. O theme.js mostra o sol com "Tema claro" no tema escuro e a lua com "Tema escuro" no tema claro.
  • Painel Aparência (data-appearance) com tema, alto contraste, densidade e tamanho da fonte. O botão fica na barra superior ou no rodapé da barra lateral, logo abaixo do botão de tema.
  • Tela inicial com o padrão Tela inicial (.start-screen). Ela usa o cabeçalho e as margens das outras telas, sem coluna centralizada, para que o título não mude de lugar entre as telas.
  • Assinatura (.app-footer) com o nome e a versão da ferramenta, o autor e a versão do Grin usada. Ela fica só na tela inicial e nas páginas de documentação ou ajuda, nunca nas telas de trabalho (listas, tabelas, formulários, análises). Ela é o último elemento do conteúdo. A tela ocupa pelo menos a altura da janela (100vh). Com pouco conteúdo, a assinatura fica no fim da janela (margin-top: auto). Com mais conteúdo, fica depois dele e rola junto. Nunca use position: fixed ou sticky.
  • Ícones do Grin para tudo o que é interface (navegação, ações, estados). Ícones próprios só para conceitos da ferramenta que o Grin não tem.
  • Fontes Geist e Geist Mono, só tokens semânticos de cor e os quatro temas funcionando.

Os arquivos para copiar

A pasta dist/ de cada versão tem o Grin inteiro em poucos arquivos, gerados por tools/bundle.mjs. Baixe a versão em Releases, não do ramo principal, que muda a qualquer momento.

ArquivoConteúdo
dist/grin.cssFontes, tokens, base e todos os componentes. Usa as fontes de dist/fonts/.
dist/grin.inline.cssO mesmo CSS com as fontes dentro do arquivo. Para ferramentas que são um único HTML e funcionam sem internet.
dist/grin.jsTodos os comportamentos num script comum, sem import. As funções ficam em window.Grin. Inclua com defer.
dist/fonts/Geist, Geist Mono e a licença OFL, que deve acompanhar as fontes.

Passos da migração

  1. Copie uma versão e anote qual

    Deixe um comentário com o número da versão e o link da release, como nos exemplos acima.

  2. Faça a tabela de equivalências

    Liste cada classe própria da ferramenta e a classe do Grin que a substitui. A busca desta documentação acha o componente pelo nome comum (modal, dropdown, tooltip).

  3. Troque as cores pelos tokens

    Toda cor escrita direto vira um token semântico, como var(--crit-fg). Nenhuma cor literal fica no CSS da ferramenta.

  4. Troque o markup, tela por tela

    Copie a estrutura de cada componente desta documentação. Mantenha os atributos ARIA, porque o estilo dos estados depende deles.

  5. Monte as partes obrigatórias

    Barra lateral do Grin, versão no logo, botão de tema e painel Aparência em todas as telas, e assinatura só na tela inicial e na documentação, como em Obrigatório em toda ferramenta.

  6. Apague o CSS antigo que sobrou

    Fica só o CSS específico da ferramenta, como uma visualização própria, sempre com tokens do Grin.

  7. Confira nos quatro temas

    Claro e escuro, cada um com e sem alto contraste, na tela de 1200 px e no celular, com o checklist de Acessibilidade.

Atualizar para uma versão nova

Leia o registro de mudanças entre a versão copiada e a nova, substitua os arquivos de dist/, atualize o comentário com o número da versão e revise as telas afetadas.
